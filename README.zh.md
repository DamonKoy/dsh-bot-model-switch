# dsh-bot-model-switch

[English](README.md) | 中文

[![npm](https://img.shields.io/npm/v/dsh-bot-model-switch)](https://www.npmjs.com/package/dsh-bot-model-switch)

在插件设置页用一张卡片，把 **DS Bot 团队里所有 Bot 的模型一次切到同一个**，或者 **逐个 Bot 单独设置**。

为 [DS Bot](https://github.com/Fei2411/DS-Bot) 而做——它是跑在 DeepSeek Harness 上的一队长期存活的 Bot。团队一旦超过几个 Bot，再挨个进各自设置卡改模型就不再是麻烦，而是偏差的来源：一半在旧模型、一半在新模型，谁也说不清现状。这个插件把这件事收成一个决定。

## 能做什么

- **批量模式**——选一个模型，应用到全部 Bot。范围可选「全部」或「除主 Bot 外全部」，写入前预览会点明哪些 Bot 会被跳过。
- **逐个模式**——每个 Bot 一行，显示当前模型、模型选择器、可选的思考强度，以及一个只读的上下文开关。只写你真正改过的行，没动的 Bot 一律不碰。
- **先预检，不是全有或全无**——接不住目标模型的 Bot 会被点名跳过，而不是让整批中断。宿主明确拒绝的算一行结果；只有网络、5xx、读不到响应这类意外才中止整批。
- **撤销**——最近 5 次记录存在 `localStorage` 的 `dsh-model-switch.undo.v1`。撤销会逐个核对 Bot 是否仍是当次写入的值，期间被别人改过的会跳过，不覆盖。
- **真回滚**——批量中途失败时，已经改过的 Bot 按反向顺序放回原值，连它写过的思考强度一起放回；放不回去的会被点名列出。
- **批量也能统一思考强度**——批量面板会向目标模型要档位（`efforts(<模型>)`），只列它真有的。只有目标模型支持该档位才下发；不支持时该 Bot 照样切模型，预览逐条标出是「仅切模型」还是带档位。
- **上下文只读**——逐个行的「上下文」开关点开后才向宿主请求 `run-stats`：最多同时 2 个、按 Bot 缓存。显示「下一轮预计占用 / 上下文窗口」；宿主没报的数显示 `—`。它只是展示，不是设置——DSH 没有 Bot 级上下文字段可写。
- **切换后回读校验**——每一轮写完会重新读一遍团队，比较每个 Bot **实际生效**的模型（逐个模式还比档位）。写进去了却没生效的会被标成「已写入未生效」：不算失败，也不触发回滚。
- **复制一行**——逐个行的 `→` 按钮把该行的模型和档位复制到其他行，纯本地操作，不落任何存储。

## 先看这条前提

**这个插件需要 DS Bot 宿主。** 它是按 DSH 0.2.1-rc.4 做的，也只在这一版宿主上实跑过。声明 `engines.dsh >=0.2.1-0 <0.3.0-0 || >=0.2.2-alpha.2 <0.3.0-0`：接受 0.2.1 整条线与 0.2.2 预发布线，拒绝 0.3.x。其中 0.2.2 线只是声明兼容、未实跑。它调用 `POST api/bot`，这是 DS Bot 在 DeepSeek Harness 之上为自己的团队视图增加的端点。原生 `dsh web` 不提供该路由，卡片能加载，但每次读取都返回 `unauthorized`，模型列表是空的。

这也是宿主半边（`lib/index.js`）故意留空的原因。所有写入都走宿主自己的 `update-bot` 端点，运行中的 Bot 引擎始终是它状态文件的唯一写入者。直接写 `state.json` 的插件会和引擎抢写，代价是丢消息——本插件不这么做。

## 安装

用 DS Bot 的插件管理器添加：

```
dsh-bot-model-switch
```

或在终端里，装进 DS Bot 实际在用的 profile：

```sh
dsh plugin --profile <profile> add dsh-bot-model-switch
```

从 GitHub 源码装：

```sh
dsh plugin --profile <profile> add github:DamonKoy/dsh-bot-model-switch
```

重启一次 DS Bot，让 bundle patch 生效。卡片随后出现在插件设置页的 **批量切换模型** 一栏。卡片只按包名 `dsh-bot-model-switch` 注册——宿主就是按这个名字认配置区的，名字对不上整块配置区都不会渲染。

## 写入方式

每次改动就是一个 `POST api/bot` 请求：`{ endpoint: "update-bot", payload: { id, model } }`；选了思考强度时是 `{ id, model, effort }`。模型列表读的是 app 自己用的同一个 `state` 端点，档位来自 `efforts(<模型 ref>)`。

- **本地 CLI 路由**（`local-*/…`）涉及模型↔CLI 换引擎的，直接跳过而不硬来：宿主要求显式 `changeEngine` 确认，而这个确认属于该 Bot 自己的设置，不该由一个批量按钮代为下发。
- 渠道**没有 API Key**（`needsKey`）的模型会从选择器里滤掉，而不是先给人选、再报错。
- **切模型时不捎带旧的思考强度**，除非你自己选；而且只发目标模型真有的档位。`update-bot` 会用新模型解析档位，解析失败发生在写盘**之前**，所以发错档位会连模型改动一起打掉。批量只列 `efforts(<目标>)` 返回的档位，逐个面板按同一口径再核一次。
- 跑在**本地 CLI 路由**上的 Bot 只保留自己那一行——换引擎要在该 Bot 自己的设置里确认，这里不代做。

## 范围与限制

- 只管**当前这台机器上这个 DS Bot 团队**里各 Bot 的模型。它不是渠道管理器、不是路由，也不负责新增或配置供应商。
- 不碰 `state.json`、不碰会话存储、不碰任何凭据。
- 除同源的 `api/bot` 外不访问网络。
- 撤销记录在浏览器里，所以是按浏览器 profile 走的，清站点数据即失效。

## 不是同一个插件

目录里另有一个他人维护的 `dsh-model-switch`。那个是在单个 Harness 会话内按角色路由模型；这个是改 **DS Bot 团队里每个 Bot 的模型**。包不同、作者不同、范围不同——按你实际在跑的东西选。
